# Subscription agent bridge

Arya's suggested provider is Claude Code. The companion runs the user's installed CLI outside the native app sandbox and returns edits through native project tools. Claude Code and Codex use their existing account sign-in. Arya does not read, copy or store provider OAuth credentials. The Anthropic API option remains separate and bills the user's API account.

On Mac, Start agent bridge copies the fixed scripts and launcher into Application Support/Reel/AgentBridge, creates a private pairing nonce, and opens the launcher in Terminal. Release builds include their signed Node.js runtime in Contents/Helpers. Source Debug builds can use installed Node.js 22 or newer. It starts a loopback listener on a free port and asks Arya to accept a nonce-bound callback. The app verifies authenticated bridge status before storing its own pairing token in Keychain. Manual pairing accepts a loopback address or a user-configured HTTPS bridge. The companion itself binds only to 127.0.0.1.

The bundled files are `editor/agent/bridge.mjs`, `mcp.mjs`, `adapters.mjs`, `protocol.mjs` and `Reel Agent Bridge.command`. They use Node built-ins. The bridge accepts a random bearer token, checks Host and Origin, and issues a separate token for each run. A run starts with a client UUID and immutable project and selection context. Repeating the same UUID and request recovers the same run; a changed request returns a conflict.

Each agent gets only `reel_api` and `reel_frame`. They can inspect project metadata, apply atomic undoable edits, import Figma frames, run native processing, and inspect native Metal frames or confined reference images. Account configuration, credentials, app launch and arbitrary external URLs are unavailable to these tools. Native routing also checks cancellation and the original project before and after a tool call.

Claude Code runs with its published binary, a strict Arya-only MCP configuration, empty built-in tools and hooks disabled for that run. Codex disables shell tools, local image reads, web search, browser and computer control, apps, plugins, hooks, memories and agent spawning for the run. It uses a read-only sandbox, ephemeral context, ignored user rules and configuration, and the Arya MCP server. Strict configuration rejects unsupported settings. The shell setting follows the [official configuration reference](https://developers.openai.com/codex/config-reference/); the installed CLI's feature list verifies the per-run feature names, including `view_image`. The installed build rejects the documented `tools.view_image` setting, so Arya uses the supported feature control instead. Subscription runs remove API-key environment overrides so an existing account login selects the intended billing path. A custom executable can receive literal argument arrays and a prompt through stdin. It manages its own sign-in and permissions.

Codex's tool host remains enabled to dispatch the two configured Arya MCP tools. Disabling that host also disables Arya tools, as the synthetic acceptance run confirmed. The independent shell, local-image, browser and computer controls remain disabled.

## Google Antigravity

Antigravity CLI 1.4.6 or newer is an available Manual editing connection. Use **Sign in to Google Antigravity** in Arya Settings, finish Google's authentication in Terminal, refresh account status, and select a listed model. The local browser editor provides the same sign-in button on macOS. iPhone and iPad use the signed-in companion Mac.

Arya launches the unmodified official `agy` binary with a separate child-process home at `~/.arya/antigravity`. The normal home and its Antigravity settings, MCP servers, hooks and plugins are not changed or loaded. Google handles credentials; Arya never reads or copies them. This separate provider profile remains between launches so you do not have to sign in for each request. Sign out by opening its sign-in window and using the official `/logout` command.

The profile's settings disable extra AI credit fallback with `useG1Credits: false`, disable telemetry, deny shell, arbitrary file and URL actions, and grant only `mcp(reel/reel_api)` and `mcp(reel/reel_frame)`. Each run gets a private temporary workspace with an Arya custom agent, an empty built-in tool list and exactly the two project MCP tools. User customizations are not inherited. No permission-bypass flag is used. Account and endpoint environment overrides are removed. Requests travel over stdin as stream-json, never in command arguments. Run credentials remain in private files and the MCP environment. The workspace is removed after the owned child exits.

Account readiness requires successful `agy models` discovery in Arya's profile, not a credential-file heuristic. The exact model IDs and labels populate the model picker. The CLI does not report model image capabilities, prices or remaining allowance, so Arya does not invent them or include those models in Auto frame-inspection requests. Manual frame inspection still uses `reel_frame` when the selected model supports image tool results. Quota failures do not enable extra credits or switch to an API key or another model.

Google retired individual-account Gemini CLI login on June 18, 2026. Arya preserves legacy `gemini-cli` settings, but disables that retired adapter and directs users to Antigravity. Repeating Google sign-in or choosing an API key does not revive that Arya connection. See [Google's deprecation notice](https://developers.google.com/gemini-code-assist/docs/deprecations/code-assist-individuals), [Antigravity migration](https://antigravity.google/docs/cli/gcli-migration/), [headless mode](https://antigravity.google/docs/cli/headless/), [permissions](https://antigravity.google/docs/permissions?tab=cli) and [credit controls](https://antigravity.google/docs/cli/credits/).

The bridge retains at most 64 MiB of request, event and tool-result JSON globally and 12 MiB per run. Delivered results are evicted first under pressure. Their hashes remain for idempotent native replies. A frame result is at most 4 MiB before base64 encoding. Runs have 30 minute deadlines, at most 128 tool calls and eight outstanding calls, and two minute tool deadlines. Provider completion gets five seconds to exit, then the companion terminates only its own child handle. Cancellation uses the same owned handle with a 1.5 second forced-termination deadline. The MCP exits when its client closes stdin.

The seven Node tests include actual stdio edits, loopback authentication, idempotent registration, cancellation ownership, route restrictions, oversized output, a completed CLI that stays alive and undelivered frame-memory limits. `AgentCompositionTests` adds real native layers, pixels, motion, generated audio, a selected title tweak and undo. To run actual provider acceptance on synthetic media, set `REEL_LIVE_AGENT_PROVIDER=codex` or `claude-code` when running that focused Swift test. It saves the project, rendered frames and report under ignored `build/agent-native-live-*`. A fixture pass or sign-in status alone does not prove a provider editing run.

Users sign in through the provider's own CLI. [Anthropic's published terms](https://code.claude.com/docs/en/legal-and-compliance) describe running an unmodified Claude Code binary with an end user's account and the conditions for offering it through a product. Arya does not provide a third-party Claude OAuth flow or intermediate subscription credentials.

## Browser editor

Browser Settings uses the same installed CLI accounts. Claude Code is the suggested default. `GET /api/assistant/status` reports installation, actual CLI account status, the selected provider and the active run. Status refreshes share one request and cache the result for 15 seconds. `checkedAt` gives the check time; loading or unavailable account status remains unknown. Provider usage limits are not reported, so `usage` is null. A startup-configured custom CLI manages its own account, and Arya does not claim that its subscription is verified.

`POST /api/assistant/config` stores only bounded provider, model and agent preferences in the project's `.reel/assistant-settings.json`. On macOS, `POST /api/assistant/login` opens a guarded command file in Terminal with the resolved installed executable and fixed `claude auth login` or `codex login` arguments. The command removes API billing overrides. A successful launch means sign-in started; the provider's status must confirm authentication. Antigravity's sign-in launcher invokes the bundled profile helper, which opens the official CLI in Arya's separate profile. A successful launch still requires an account-status refresh before editing. Custom executable paths and literal arguments can be supplied only when starting the server with `--custom-executable` and repeated `--custom-arg` flags.

Browser prompts use an owned in-process companion with a private token. The browser receives run IDs and status, not pairing or run tokens. The immutable context includes the project epoch and version, selected clips or transitions, composition, playhead and attached references. The agent receives the existing two Arya tools. File reads stay inside the project, frames are at most 4 MiB, and JSON tool results are at most 512 KiB. Transcript reads use bounded word pages. Account settings and sign-in remain unavailable to agent tools.

Each project commit checks the active run, project epoch, current disk contents and the version captured before the tool's awaits. Durable transcript publication uses the same guard. Cancellation stops only the owned CLI and jobs that its tool context created; an existing user transcription job remains active when the agent reuses it. Interchange proxy imports dispatch internally so they keep that context. Exports stay in `renders/`, refuse referenced source destinations and cannot reopen a completed job. Related edits keep ordinary undo history and identify their activity as agent edits. Editor chat starts a separate CLI run, including when the Claude Code plugin opened the editor. It does not send messages to the terminal session. Legacy plugin relay sends are rejected because that connection has no verified AI recipient.

The browser backend fixture suite uses actual local CLI subprocesses and HTTP tool dispatch. It covers editable layers and selection edits, fixed sign-in arguments, unknown account limits, cancellation ownership, registration failures, stale projects, preserved corrected transcripts, confined reads and writes, and undo. These fixtures do not prove a live subscription editing run.
